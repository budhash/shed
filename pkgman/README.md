# pkgman

Universal package manager CLI with state tracking and manifest-driven installation across 13 different package managers.

## Overview

`pkgman` is a stateful wrapper providing unified package management across brew, apt, dnf, cargo, go, npm, pipx, mas, github, download, script, cask, and dmg. It tracks package installations and versions in configuration files, reconciles system state with declarative manifests, and provides convenience commands for day-to-day package operations.

**This README documents the AS-BUILT implementation.** It supersedes archived design docs (`pkglib-design.md`, `testing-pkgman.md`), which referenced `packages.cfg` paths that are no longer current.

## Architecture

pkgman is built in two layers:

- **`pkgman`** (stateful CLI) — handles CLI parsing, state management, and manifest processing. Reads/writes configuration and status files. Implements `install`, `sync`, `add`, `remove`, `status`, `list`, `provision` commands.
- **`pkglib`** (stateless handlers) — provides package manager abstractions. Each manager (brew, apt, dnf, etc.) gets a set of operations (validate, install, update, uninstall, status) via `pkglib.<manager>.<operation>` functions. Called by pkgman with metadata and kwargs.
- **`pkgboot`** (bootstrap) — sourced by the script handler when provisioning script-based managers. Manages bootstrap script lookup and execution.

## Managers

13 package managers are supported:

| Manager | Type | Notes |
|---------|------|-------|
| `brew` | CLI | macOS package manager |
| `apt` | CLI | Linux (Debian/Ubuntu) |
| `dnf` | CLI | Linux (Fedora/RHEL) |
| `cargo` | CLI | Rust packages |
| `go` | CLI | Go packages (go install) |
| `npm` | CLI | JavaScript packages |
| `pipx` | CLI | Python isolated installs |
| `mas` | CLI | macOS App Store (requires MAS CLI) |
| `github` | API | Release artifacts from GitHub repos |
| `download` | HTTP | Direct URL downloads |
| `script` | Custom | Shell scripts (sourced from filesystem or URL) |
| `cask` | Template | Homebrew cask (delegates to brew with `--cask`) |
| `dmg` | Delegator | macOS disk images (delegates to download handler) |

Managers are referenced by name in manifest rows. Unknown handlers warn and skip the row without aborting.

## State Layout

All state lives in `$PKGMAN_CONFIG_DIR` (default: `${XDG_CONFIG_HOME:-$HOME/.config}/pkgman`). The directory structure:

```
~/.config/pkgman/
├── index/                      # Source-of-truth index files
│   ├── package.core.cfg        # Core-scope packages (converged by sync --prune)
│   ├── package.system.cfg      # System-scope packages (never pruned)
│   ├── package.manager.cfg     # Manager-scope packages (never pruned)
│   └── package.*.cfg           # Custom scopes (never pruned)
├── .resolved.cfg               # Merged index (regenerated on read)
└── status.cfg                  # Status and metadata
```

### index/package.*.cfg (index files)

Source of truth for declared packages. Each row is:
```
<name>.<field>=<value>
```

Example:
```
docker.manager=brew
docker.source=docker/docker
docker.desc=Container runtime
docker.params=--cask
docker.tags=mac,laptop
docker.version=25.0.1
docker.scope=core
```

Fields are: `manager`, `source`, `dest`, `artifact`, `channel`, `scope`, `os`, `sudo`, `detail`, `tags`, plus any custom kwargs from the manifest.

### .resolved.cfg

Auto-generated by merging all `index/package.*.cfg` files. Ephemeral; never edit.

### status.cfg

Runtime state (status + metadata):
```
<name>.<field>=<value>
```

Fields: `status` (installed/missing/unknown), `install_method` (pkgman/manual/unset), `installed_at` (timestamp), `last_checked` (timestamp).

**Critical property**: `install_method=pkgman` is written ONLY by successful `pkgman install`. Add-only packages (via `pkgman add`) have no `install_method` key. Manual installs get `install_method=manual`. This distinction is used by `sync --prune` to preserve manually-installed packages.

## Manifest Grammar

Manifests are plain text files declaring packages to manage. Each non-comment row is:

```
name | handler | desc | params | tags
```

| Field | Purpose | Notes |
|-------|---------|-------|
| `name` | Package identifier | Must be a valid shell identifier |
| `handler` | Manager type | One of the 13 managers above; unknown handlers warn+skip |
| `desc` | Human description | Free text; for documentation only |
| `params` | Key-value parameters | Format: `key=value!key2=value2!...` (`;` also accepted); passed to pkglib handlers as kwargs |
| `tags` | Filtering rules | Comma-separated: OS tags (mac, linux) and/or host tags (laptop, macmini, server); empty/untagged rows apply to all |

**Params detail**: Parameters from the manifest become kwargs in pkglib handler calls. Special kwargs include standard metadata (`manager`, `source`, `dest`, `scope`, `tags`). Custom kwargs like `version=1.2.3` are ordinary parameters passed to the handler; pkgman never reads or validates them — they come from the caller (manifest or CLI).

**Tags detail**: Tags filter which rows apply to the current operation. The `--host <hostname>` flag selects which host tags match. OS tags (mac, linux) auto-match based on the current system. Both must pass for a row to be included (i.e., tags are AND'd).

Example manifest:
```
# name    | handler | desc          | params                              | tags
docker    | brew    | container mgr | --cask                              | mac
python    | brew    | python 3      |                                     | 
rust      | cargo   | rust toolchain| --default-host x86_64-unknown-linux | linux
app       | script  | custom app    | source=https://example.com/app.sh   | mac,laptop
```

## Commands

### install <manifest> --host <hostname>

Install all declared packages matching the host/OS tags from a manifest file.

- Creates tracking entries in `index/package.core.cfg` and `status.cfg`.
- Writes `install_method=pkgman` to status.cfg for each successful install.
- Unknown handlers warn and continue; manifest processing doesn't abort.
- Already-tracked packages are idempotent (no-op if already installed).
- **Requires `--host`** — tells pkgman which host tags to match.

Example:
```bash
pkgman install ~/my-packages.manifest --host laptop
```

### sync <manifest> --host <hostname> [--prune] [--force] [--dry-run]

Reconcile system state with manifest. Installs missing, updates outdated, removes undeclared (with `--prune`).

- By default: plan-only (shows what would change); confirm once unless `--force`.
- `--dry-run`: report without acting.
- `--prune`: remove ONLY core-scope packages with `install_method=pkgman` that are undeclared in the manifest. Never touches system-scope, manager-scope, or `install_method=manual` packages.
- **Fails safely on parse errors**: rows with unknown handlers still declare their package name and prevent prune of that name (never silently removes a package whose row failed to parse).
- **Requires `--host`** — tells pkgman which host tags to match.

Example:
```bash
pkgman sync ~/my-packages.manifest --host laptop --prune --force
```

### add <handler> <name> [--key=value...]

Track an existing package without installing it (add-only, for manually-installed packages).

- Creates tracking entry in `index/package.core.cfg`.
- Does NOT write `install_method` to status.cfg; preserved by `sync --prune`.

Example:
```bash
pkgman add brew docker --detail "manually installed"
```

### remove <name>

Stop tracking a package (does not uninstall).

### status <name>

Show installation status and metadata for a package.

### list

Show all tracked packages and their statuses.

### provision <manager>

Provision/bootstrap a manager (e.g., `provision brew` installs Homebrew). Uses pkgboot to find and execute bootstrap scripts.

## Lock-Ignorance

pkgman **does not read or enforce lockfiles**. The `version=` parameter in a manifest is an ordinary kwarg — it comes from the caller (the manifest or command-line) and is passed unchanged to the handler. pkgman stores it as metadata but never validates it against installed versions or external locks. This is by design: pkgman tracks *declarations* (what was declared when), not version constraints.

## Dependencies

### loam library

`pkglib` sources `loam`, a generic bash stdlib providing logging, OS detection, filesystem ops, UX prompts, and smart downloads.

Sourcing strategy (in order):
1. `$LOAM` environment variable (if set and file exists)
2. In-repo relative path: `../lib/common/loam/loam` (relative to pkglib location)
3. Error if not found

See [lib/common/loam/README.md](../lib/common/loam/README.md) for loam's API and requirements.

## Bash Compatibility

- **bash 3.2+** (tested on 3.2 and 5.x in CI)
- Uses bash 3.2-compatible empty-array idiom: `"${_array[@]+"${_array[@]}"}"`
- No bash 4+ features (associative arrays, namerefs, etc.)
- Compatible with macOS system bash (3.2)

## Examples

### Single-host manifest

```
# my-mac.manifest
docker    | brew    | Docker        | --cask              | mac
python    | brew    | Python 3      |                     | mac
jq        | brew    | JSON CLI      |                     | 
go        | brew    | Go toolchain  |                     | mac,laptop
```

Install on laptop (matches mac + laptop tags):
```bash
pkgman install my-mac.manifest --host laptop
```

Sync (converge to manifest, remove undeclared core packages):
```bash
pkgman sync my-mac.manifest --host laptop --prune --force
```

### Multi-host manifest

```
# workstations.manifest
docker    | brew    | Docker        | --cask              | mac
python    | apt     | Python 3      |                     | linux
nodejs    | npm     | Node.js       |                     | 
vim       | brew    | Vim editor    |                     | mac
vim       | apt     | Vim editor    |                     | linux
```

Install on a Linux server:
```bash
pkgman install workstations.manifest --host server
```

### Custom params and versions

```
# app-bundle.manifest
app-v1    | script  | Custom app    | source=./install.sh!version=2.0!env=prod | mac,laptop
rust      | cargo   | Rust          | --default-host x86_64-apple-darwin       | mac
```

Parameters are passed to handlers; version is stored as metadata but not enforced.
